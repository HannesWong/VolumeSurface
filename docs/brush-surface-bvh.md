# 表面 BVH 笔刷加速

## 目标

笔刷的候选查询按表面分组进行。笔划新增一段曲线时，算法先在物理坐标中排除不可能受影响的表面组，再进入少数 VDB 叶节点做精确的 26 邻域传播。

本阶段不改变笔刷权重、法线惩罚、平面度或 26 邻域连通规则。它只改变候选表面的组织方式和重复预览时的工作范围。

## 分层数据

底层单元是 VDB 的已有 leaf 节点。每个 leaf 保存其 index-space 边界及换算后的 world-space AABB。它仍是精确体素数据的拥有者，不复制为三角网格。

上层是一次构建、只读的 BVH。每个内部节点保存其子节点 world-space AABB。该 AABB 采用真实世界单位，所以 XY 0.31 mm 与 Z 约 1 mm 的非等距体素不会把查询半径变形。

BVH 首先只承担保守的空间裁剪。法线锥、平面度和表面连通 patch 将在后续阶段作为节点摘要加入；它们不能在没有安全上界时直接排除候选组。

## 查询规则

新中心线段会扩展为半径为 `core + falloff + planarity halo` 的胶囊体。BVH 节点与该胶囊体不相交时，整个节点及其子树不访问。

命中的 leaf 会额外加载一层满足梯度、法线和平面度计算需要的 halo。只有这些 leaf 中的体素可以进入精确曲面分类、路径寻路和传播。

所有 BVH 测试必须对胶囊查询保守：允许留下假阳性，但绝不允许剔除与查询胶囊及其 halo 相交的有效表面体素。

## 增量笔划

后续中心线拟合会把已提交的前段视为不可变。一次新预览只提交新增尾段及其必要的连接段；此前段的热力图权重保留在 Viewer 中，不重新计算。

曲线拟合升级为局部支持 B-spline 时，已提交 span 不再受之后的控制点影响。当前阶段先保留原始锚点的精确曲面路径，BVH 和增量传播接口会为该升级提供稳定的尾段边界。

## 验证

单元测试验证 BVH 胶囊查询不会漏掉与胶囊相交的 leaf，并验证使用 BVH 的笔刷结果与原始局部块结果在小型 VDB 上一致。

Viewer 回放使用已有 `brush_profile.jsonl`。比较整笔累计热力图覆盖和最终三角形数；`block` 和 `route` 的单轮工作量应随新增尾段而不是整笔路径增长。

## 非目标

本阶段不把 VDB 自动视为 LOD 系统，也不以近似方式替代最终精确笔刷结果。显式的交互分辨率层级和 GPU 热力图局部上传将在 BVH 路径稳定后单独处理。
